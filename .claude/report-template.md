# Maestro Test Report Template

This file defines the structure, styling, and content requirements for test reports.

## Report Format

**Primary Format:** HTML (single file with embedded screenshots)
**Output Location:** `reports/{app-name}-test-report.html`
**Naming Convention:** `{app-name}-test-report.html`
**Storage Directory:** All reports must be stored in the `reports/` directory

## Report Structure

### 1. Header Section
```
- Report Title: "{App Name} {Platform} Test Report"
- Subtitle: "Automated UI Testing with Screenshots"
- Timestamp: Generated date and time
- Color Scheme: Gradient background (#667eea to #764ba2)
```

### 2. Summary Dashboard

Display as grid cards with the following metrics:
- **Total Tests**: Number of test flows executed
- **Passed**: Number of successful tests (green)
- **Failed**: Number of failed tests (red)
- **Success Rate**: Percentage (green if 100%, yellow if 80-99%, red if <80%)
- **Total Commands**: Sum of all commands executed
- **Screenshots**: Total number of screenshots captured
- **Duration**: Optional - test execution time

### 3. Device Information

Display in a bordered card with grid layout:
- Device Name (e.g., "iPhone 16 Pro")
- iOS/Android Version
- Platform Type (Simulator/Emulator/Physical)
- Device ID (full UUID)
- App ID/Bundle ID
- Test Date/Time

### 4. Test Results Section

**For each test flow:**
- Test name as heading with badge (PASSED/FAILED)
- File path to test flow
- Number of commands executed
- Status message
- Detailed result description

### 5. Screenshot Gallery

**Layout:** Responsive grid (3 columns on desktop, 1-2 on mobile)
**Storage:** Store the screenshots in a dedicated screenshots directory and use that path to add them in the report.

**Each screenshot card includes:**
- Step number (circular badge with gradient)
- Screenshot title (descriptive action)
- Full-size screenshot image
- Description text (explain what happened in this step)
- Click to enlarge functionality

**Screenshot Order:** Sequential (01, 02, 03...)

**Screenshot Descriptions Pattern:**
```
Step 1: "Wikipedia app successfully launched with clear state. Initial screen loaded and ready for testing."
Step 2: "User onboarding flow initiated. Elements loaded successfully from screen definitions."
Step 3: "[Action performed]. [Result/state after action]."
```

### 6. Footer
- "Powered by Maestro Mobile Testing Framework"
- "Generated by Claude Code Automation"
- Timestamp (optional)

## Styling Guidelines

### Colors
- **Primary Gradient**: `#667eea` to `#764ba2`
- **Success**: `#28a745` (green)
- **Warning**: `#ffc107` (yellow)
- **Error**: `#dc3545` (red)
- **Info**: `#667eea` (blue)
- **Background**: `#f8f9fa` (light gray)
- **Text**: `#333` (dark gray)
- **Muted Text**: `#6c757d` (gray)

### Typography
- **Font Family**: `-apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, Oxygen, Ubuntu, Cantarell, sans-serif`
- **Heading Sizes**: h1 (2.5em), h2 (1.8em), h3 (1.1-1.3em)
- **Body Text**: 1em with 1.5 line-height

### Layout
- **Max Width**: 1400px for main container
- **Padding**: 40px for sections
- **Border Radius**: 8-12px for cards
- **Box Shadow**: `0 4px 12px rgba(0,0,0,0.1)` for cards
- **Grid Gap**: 20-30px

### Interactive Elements
- **Hover Effects**:
  - Cards: `translateY(-5px)` and enhanced shadow
  - Screenshots: `scale(1.02)`
- **Modal**: Click screenshot to view full-size in dark overlay
- **Transitions**: 0.2-0.3s for smooth animations

## Screenshot Embedding

**Method:** Base64 encoding embedded in HTML
**Format:** `<img src="data:image/png;base64,{base64_data}">`
**Benefits:** Single portable file, no external dependencies

## Screenshot Descriptions Template

Use this pattern for generating descriptions:

```yaml
01_app_launched: "Wikipedia app successfully launched with clear state. Initial screen loaded and ready for testing."

02_onboarding_start: "User onboarding flow initiated. Elements loaded successfully from screen definitions."

03_onboarding_progress: "Progressing through onboarding screens by tapping 'Next' button until data privacy screen appears."

04_data_privacy_screen: "Data privacy consent screen reached. 'Get Started' button is visible and ready to be tapped."

05_after_get_started: "Successfully accepted data privacy terms. Bottom sheet appeared with additional options."

06_home_screen: "Main home screen loaded successfully. Bottom sheet dismissed, ready for primary app interactions."

07_after_swipe: "Swipe gesture executed from [coordinates]. Screen state after user interaction completed."
```

## Responsive Design

- **Desktop (>1200px)**: 3-column screenshot grid
- **Tablet (768-1200px)**: 2-column screenshot grid
- **Mobile (<768px)**: 1-column screenshot grid
- All cards stack vertically on small screens

## Accessibility

- Semantic HTML elements
- Alt text for all screenshots
- Keyboard navigation support (ESC to close modal)
- Sufficient color contrast for text
- Clear focus indicators

## Report Generation Process

When generating a report:

1. **Run tests** with screenshot capture enabled
2. **Collect data**:
   - Test results from Maestro output
   - Screenshot files from `screenshots/` directory
   - Device information
   - Timestamps
3. **Convert screenshots** to base64
4. **Generate HTML** using template structure
5. **Embed screenshots** as data URIs
6. **Save report** to `reports/` directory with naming: `reports/{app-name}-test-report.html`
7. **Provide path** to user
